# v0108 - native boss death to dungeon gem

Original type 07 dispatches to 4BA4..4C5C. The previous port's lethal damage handler already converted a defeated boss to type 07, but that type had no behavior. It now records progression value 01 at C0CE plus the dungeon byte, clears the eight transient actor slots, hides the boss/removes its boss flag, starts the original 180-tick counter, and attempts bounded death-particle creation. At expiration, the next behavior tick requests SFXB0 and converts the primary record to type 0F for dungeons below 10. The existing gem sequence then takes over. Dungeon values >=10 set hero state 12 at entry and game state 14 at completion, exactly as the original; the ending dispatched by state 14 remains unimplemented.

The original game does not call music selection 1CAF during boss death or while the spawned gem awaits collection. The previous per-frame native music check instead switched from 86 to 83 after the boss flag disappeared. A controlled dungeon fixture with the boss theme selected reproduces the discrepancy at the second death tick on v0107. The native death path now holds that selection until collection or the next actor/room load. The gem frontend then performs its normal reward cue and dungeon-music restoration. Live comparisons include source/native music identifiers through all 191 death/appearance frames and final collection; dungeon fixtures explicitly seed the boss theme because the test relocates from the entrance room. This validates selection/retention, not audio waveform equivalence.

Particle placement scans for the first free slot among actor slots 8..15, performs the source byte-wrapped X/Y computations and bounds, and writes only position/type/state/previous-type fields. Existing death-particle behavior animates/removes them. The source LD A,R gate and 04E1 placement input are still supplied by provisional SGDK random in production. Therefore actual source/native particle sequences and positions differ; matching them requires porting the source refresh/random stream. This is explicitly unfinished, not an exact random emulation.

The continuous death-to-gem test exposed a one-frame delay in gem collision-box publication at its first appearance. The SMS renderer 0940 follows the actor update 26B6, making the new boxes available for the next simulation iteration before the delayed hardware SAT. The native actor tail now commits the gem descriptor's collision boxes at that point. v0106 is retained as an intermediate build to avoid. v0107 additionally revealed premature boss music switching and is also intermediate.

Separate fixtures execute original 4BA4..4C5C and 4C0C..4C3E unchanged. 3072 placement cases enumerate all 256 placement bytes, four interior/edge positions and first-free slots 0,3,7. Thirty-six state cases combine dungeon bytes 1,9,10,FF with states 0,2,4 and counters 1,2,180; occupied transient slots suppress spawning while leaving original LD A,R intact. All 768 actor-record bytes, 256 progression bytes, hero/game states, sound request and actor count match the compiled production helpers. The native harness copies the production source and publishes explicit volatile result fields to prevent optimizer removal.

Production-game-loop checks seed an actual type-64 boss record with one HP, one pending damage point and a one-tick freeze to skip its AI before lethal damage. The original/native hurt tails then perform the conversion to type 07. Eighteen cases cover all nine dungeon indices in PAL/NTSC, with the transient pool temporarily occupied to isolate deterministic death timing. Another two cases execute in boss room 115 after normal dungeon entry. Primary records and progression/room flags match on all 191 frames from the lethal tick through gem appearance, followed by reward-window and final-stat comparisons. Four further cases leave particles active in exterior/dungeon PAL/NTSC fixtures: the primary timeline still matches, and each implementation generates valid type-1 particles within original bounds. Those particle arrays are not asserted equal. Representative actual particle screenshots were inspected.

Health-cap boundary and physical gem-pickup checks are rerun, alongside ordinary PAL/NTSC movement/scroll/enemy timing and six inventory returns. The scope audit reconstructs v0105 after removing only boss-death helpers, their dispatch/music retention and the gem collision-box publication. Existing gem assets are byte-identical to v0105.

This does not establish natural complete boss fights, boss AI, original RNG, the final ending, full framebuffers/hardware timing, audio waveform equivalence or a complete playthrough. Last HP/damage and scene setup are controlled inputs. Exact global loading/modal/refill timing and save/cold-load progression still need work. Full game port remains incomplete.
