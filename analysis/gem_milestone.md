# v0105 - native dungeon gem appearance and collection

Original type 0F dispatches to 2A6B..2ACC. The previous production port could create the record after conditional actor loading, but did not implement its behavior or fixed-ROM sprite descriptor. The native object now initializes the source tile/descriptor at X=128,Y=28, clears C0AE, waits for hero state 1 to become collectible, and uses the original contact/damage pickup condition. The existing actor tail and renderer retain their normal ordering.

Collection clears the record and requests SFX96, writes 80 to C0CE plus the dungeon index, and uses the original per-dungeon reward number (tile + 9F, byte arithmetic). The acquisition frontend now supports all nine original labels, the five-sprite hero pose, and the one-tile glyph icon copied by 2B2C/2B44. Only 32 icon bytes are written; the other 96 bytes are preserved. Initial icon attempts incorrectly enlarged the glyph; those intermediate ROMs remain archived. The final implementation also performs the 631A/631D persistent room marking and acquisition transformation before showing the window. After acknowledgement, it applies original byte-sized health-cap growth with the 81 threshold, refills magic and health, and restores room music.

Resources are extracted from the original ROM: tile lookup at 1EDC, fixed descriptors 2ACD..2ADC, reward label pointers at 63B3, glyphs decoded from 13701 into original VRAM3040, and the source hero pose at ROM304A1. No emulator-captured bitmap is embedded in production. Descriptor lookup now handles the fixed gem interval as well as existing actor/axe descriptors.

Current v0105 validation has 26 controlled production-game-loop cases: all nine gems in PAL and NTSC (18), health-cap boundaries 120 and 128 in both regions (4), actual physical hero contact in both regions (2), and boss room 115 after normal dungeon entry in both regions (2). Source and native appearance records, all persistent room flags, progression and final health/magic fields match. Stable reward software maps and 35 used tile pixel arrays match. Unused icon-tail bytes are unchanged; source and native tails can already differ before the window, so their equality is not claimed. Actual VDP gem sprite entries and glyph pixels, and complete five-sprite reward SAT lists match for all 18 standard cases. Representative SMS/MD reward frames were visually inspected, including the normal MD vertical placement.

Existing 22 stationary item reward/refusal cases pass in each region, exercising the shared frontend. Ordinary PAL/NTSC movement, three scroll directions and eight deterministic enemy motions pass, as do all six inventory-return cases. A source scope audit reconstructs the v0101 production files after removing only gem behavior/dispatch, descriptor support and the reward frontend variant.

These are controlled fixtures, not a natural boss victory or full playthrough. Boss death type 07 (4BA4 onward) still needs its progression write, particles and eventual gem creation; boss AI, final dungeon/ending, quest conditions and remaining abilities are unfinished. The original refresh-register randomness is not reproduced. Exact modal/refill timing, complete framebuffers, all dungeon room-specific redraws, gem SRAM cold-load persistence and audio waveform equivalence are not established by these checks. Known global timing discrepancies remain.
